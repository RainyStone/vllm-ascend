# 性能劣化与首token一致性：当前证据

正式矩阵已完成，补充诊断尚待用户确认。此文区分观察到的现象、实现事实与尚未证实的根因。

## 性能现象

- 两对独立起服都劣化：Slot TTFT分别增加6.17%和6.04%，输入吞吐分别下降5.56%和5.50%。
- 两对等权平均：off TTFT14443.17 ms，Slot15324.92 ms（增加6.10%）；off输入吞吐62267.01 token/s，Slot58820.55 token/s（下降5.53%）。
- 四个输入长度分组的TTFT都变慢：<=32K增加4.97%，32K~64K增加7.52%，64K~96K增加7.02%，96K~128K增加5.48%。因此现象不是只集中在最长输入组。分组结果仍含并发调度与排队影响，不能视为纯模型单请求执行时间。

## 是否因为不均衡不够

当前不能下结论。正式脚本未开启逐层rank负载采集，现存TTFT、token总量和服务日志无法还原逐step/layer专家负载。不能回填一个推测的不均衡比。

已准备独立off/slot补采脚本，使用同316条数据、并发16，分别保留：
1. 专家按归属rank累积的原生负载（Slot重分配前）；
2. 每个rank实际计算的负载（Slot重分配后）；
3. rank峰均比、专家峰均比及每rank归一化负载，逐step/layer及分布；
4. Slot按全局专家ID统计的路由/实际计算条目守恒、远端专家条目数量。
统计轮会产生开销，绝不混入上面的正式性能数据，也不冒称是原12轮的逐步记录。

## 已确认的额外路径，尚未量化其贡献

- Slot每层dispatch后调用prefetch_projections，W4A8MXFP需要w13/w2和两份scale，共四类payload；API逐projection调用prefetch。即使某次计划没有有效remote GET，也仍有这条调用路径。实际GET数量/时间尚未采集。
- 本轮关闭持久专家缓存、提前预取、独立prefetch流；因此没有通过这些机制隐藏/消除权重预取开销。三项已开的优化主要去掉额外barrier/reconcile/source-dup，仍保留规划、dispatch、四payload预取与combine。
- Slot按[32个home+32个slot]别名运行统一MLP；原生路径按本地专家分组。工作分配与算子输入布局会变化，不能预设其GEMM效率与数值完全一致。
- 量化payload镜像保留了原始权重；日志明确release skipped。它增加显存占用，两组固定KV同为24GiB，因此不是“Slot减少了KV”的配置差异。额外占用是否造成性能影响未证明。
- REAL_T=1且NO_SYNC默认1，不能用旧的容量padding或.item()同步路径直接解释本轮劣化。
- 当前缺少本工作负载的device trace或同步分项计时，无法把6.10%分摊给规划、权重搬运、GEMM和combine，也不能从旧实验注释的耗时拼出本次根因。

## 首token差异的证据

- 计入比较的轮次：跨模式两对、每对round2/3，共1264次同样本比较，911次文本相同，约72.07%。
- 同模式round2/3的四台服务合计1208/1264相同，约95.57%。
- 汇总每模式4次测量：67条样本在off内4次都相同、在Slot内4次也都相同，但两模式不同；206条所有测量相同；43条至少一模式有变化。
- 因此存在可复现的跨模式差异，不能仅以“off自己也会变”排除Slot路径问题。
- 输入全文SHA256、输入token数、输出1token均已逐条校验；12轮模式门禁记录的3份关键源码哈希一致。模型权重字节与每层中间结果尚未做逐项对照。

## 精度根因候选与待验证项

源码已经确认：MoonEP先把专家输出与FP32路由权重相乘并转回BF16，再由combine将BF16行转FP32求和；原生ALLTOALL交给weighted-unpermute融合加权归并。不同舍入位置可能导致数值不一致，但尚未通过算子实验确认原生算子的实际计算语义，更没有证明它是端到端差异的唯一原因。

还需排查权重/scale搬运内容、Slot专家映射与计数守恒，以及不同分组/批次下的量化GEMM。当前没有证据确认这些环节存在错误，也没有完成排除。

已选8条固定样本并准备重复请求+top-logprobs检查，用于判断差异是否可复现、两候选token的margin是否接近；另备有单卡weighted-reduce公式对照工具。均未执行NPU补充诊断。

本轮采用原始LongBench-v2 completions模板，未套chat模板，且max_out_len=1，首token常是引号等格式字符。因此这里讨论的是数值/执行一致性，不能据此评价完整LongBench答题准确率。
