# 8卡收益阈值自适应二分摸测：1.00–1.75

日期：2026-11-03。主机141.61.45.118，容器xzx_moonep。
本方案替代之前1.00–2.50的粗扫/细扫方案。本次仅准备脚本和纯逻辑验证，不执行服务或实验，等用户通知。

## 已确认参数

- 搜索范围严格限制在1.00–1.75，候选区间宽度≤0.05后停止。
- 每个点两对独立off/slot服务，一对off→slot，另一对slot→off。
- 每台先做2请求×1024输入的预热，再测3轮，丢弃第1轮，取第2/3轮均值。
- 每对独立判断：TTFT降低≥3%，且输入吞吐提高≥3%，两项都满足才记为达标。
- 两对都达标：gain；两对都不达标：no_gain；一对达标另一对不达标：uncertain，立即停止。
- 不自动加第三对，不用两对的平均收益覆盖投票分歧。
- 延续8卡DP8/TP1/EP8、8K输入/8K token预算、输出1 token、并发16、32请求、
  每卡4GiB KV、max-model-len=8193，slot三项优化不变。
- 模型仍为/mnt/share/weight/DeepSeek-V4-Flash。

## 算法

1. 先测上端1.75。若两对都不达标，停止：未建立二分区间，不能断言区间内部全部无收益。
2. 若1.75达标，再测下端1.00。
3. 若1.00也达标，停止：最小允许测试点已达标，本范围没有“不达标→达标”夹逼区间。
4. 若1.00不达标、1.75达标，建立(low,high]。
5. 测中点m=(low+high)/2：m达标则high=m，m不达标则low=m；uncertain或数据失败则停止，原边界不变。
6. high-low≤0.05时报告候选区间；不报告未测试的精确阈值。
7. 若已测数据出现较小s达标、较大s不达标的矛盾，停止并报告非单调；不继续强行二分。

第一个中点为1.375。之后的点位由真实数据决定，不能预先固定为一张扫点表。
例如以下是**算法示意，不是实验结果**：
1.75达标 → 1.00不达标 → 1.375不达标 → 1.5625达标 → 1.46875达标 → 1.421875达标，
则报告(1.375,1.421875]，宽0.046875。

## 适用前提和结论边界

二分依赖“达标谓词在这个范围近似单调”的假设。有限稀疏采样无法证明未测区间不存在收益孤岛或回落。
因此结论只能是本配置、固定路由族、近似单调假设下的探索性候选区间，
不是统计显著性认证，也不是普遍成立的“所有更高s都获益”阈值。
两对一致仍不能消除噪声，只能比单对判定保守一些；分歧时按用户要求停止等待复测决策。

这里no_gain指两对各自均未同时达到两项3%条件，不表示slot必然比off更差。
两对的平均收益仅作描述，判定依据是每对独立是否达标；每台服务内多轮不算独立重复。

## 路由和对照控制

沿用同一DP8两热点路由族：E=256、K=6，每rank32专家，热点始终是rank0的expert 0和16。
只连续改变这两个热点份额，其余254个专家均分剩余份额。
s=最大home-rank路由份额/平均份额，平均为12.5%；不是单专家峰均比或slot后的实际计算峰均比。

令每个热点份额为p%，由12.5s=2p+30(100-2p)/254解出p。
每个动态点归档路由全文、目标/理论比例、有限token整数分配估计和SHA256。
不改变热点数量、位置、KV、并发、输入长度或token预算来凑收益。

同一off/slot对使用相同server/route/bench seed和相同请求形状；
不同对用不同bench seed块，相同对序号在不同s复用相同prompt seed。
两种模式相邻运行，所有点都含AB/BA顺序，减少模式先后顺序偏差。
不开profiling、balance或time-stats等性能诊断计数。

## 工作量

理想正常路径：2个端点+4个中点=最多6个不同s点。
每点2对×2模式=4次起服，总计最多24次起服、96次bench调用（含预热）。
区间宽度0.75/2^4=0.046875。
相比0.05逐点扫描16个点，正常路径测试点数减少62.5%。

按此前每个服务约4–5分钟的实际经验估计，完整正常路径约1.5–2小时，受加载与资源释放速度影响。
若上端不达标或某点两对分歧，会提前停止；不自动扩大范围或加测。
失败后人工决定续跑时，重跑次数不包含在理想24次起服预算内。
