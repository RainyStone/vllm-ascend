# moonep off 与 moonep slot 实验数据报告

这份报告把 22 次运行、870 次 vllm bench 的结果按「服务配置 → 路由仿真分布 → bench 输入 → 每次 bench 的原始指标」
四级摆开，同一格子里 moonep off 与 moonep slot 紧挨着，方便直接对比。

数据全部来自 vllm bench 写出的 json 原始字段（不做跨轮中位之类的二次统计）。
字段含义与完整 41 列见原始导出目录 `/tmp/mc2_probe/export/`（`00_README.md` 与 `04_bench_results_raw.tsv`）。
本报告每张表的每一行，都能在 `04_bench_results_raw.tsv` 里按 `运行名` + `形状` + `轮次` 三列找回，
原始 json 在 `/tmp/mc2_probe/grid/<运行名>/<形状>_c<轮次>.json`，原始服务日志在 `/tmp/mc2_probe/grid/<运行名>.log`。

本报告由 `/tmp/mc2_probe/gen_experiment_report.py` 生成（只读 `/tmp/mc2_probe/export/`，不连服务）。
**报告本身放在仓库里（本文件），原始数据与脚本在 `/tmp/mc2_probe`**：要复现或核对，两边都得留住。

HTML 版（同样内容，另外把 moonep off 与 moonep slot 的变化算好、多级可折叠）在同一目录：
`moonep_off_vs_slot_bench_data_report.html`，由 `/tmp/mc2_probe/gen_experiment_report_html.py` 生成。

## 怎么读

- 第 1 级「服务配置」= 一次或几次**服务启动**用的参数。同一份服务配置下所有运行共用同一批 bench 输入。
- 第 2 级「路由仿真分布」= `VLLM_ASCEND_MOE_SIM_ROUTE` 的档案（`sim_route_*.txt`），决定专家被 route 到哪个 rank。
- 第 3 级「bench 输入」= 一种形状：`num_prompts`（请求数）、`max_concurrency`（并发上限）、`random_input_len`（输入长度）、
  `random_output_len`=1（每个请求只生成 1 个 token）、实际并发 = min(max_concurrency, num_prompts)。
  seed 由 `bench_grid.sh:77` 定为「形状序号 × 1000 + 轮次」，**跨运行同形状同轮次用同一个 seed**，
  即两条运行看到的是同一批 prompt，这是 off 与 slot 能逐格对照的前提。
- 第 4 级就是表里的行：每次 bench 一行，`模式` 列区分 moonep off / moonep slot。

每个 bench 输入都跑了 3 轮（`轮次` 1/2/3）。**轮次 1 是服务刚拉起后的第一轮，前面的分析按热身剔掉**，
本报告保留原始值，你自己看时请以轮次 2、3 为准。

表里的列：

- `完成/失败` = json 的 `completed` / `failed`（请求数）
- `duration` = json 的 `duration`（秒，整次 bench 的墙钟）
- `TTFT 平均` / `TTFT p50` / `TTFT p90` / `TTFT p99` = json 的 `mean_ttft_ms` / `p50_ttft_ms` / `p90_ttft_ms` / `p99_ttft_ms`（ms）
- `E2EL p50` = json 的 `p50_e2el_ms`（ms；`random_output_len`=1，所以它和 TTFT 只差那一个 token 的生成时间）
- `请求吞吐` = json 的 `request_throughput`（req/s）；`总 token 吞吐` = json 的 `total_token_throughput`（token/s）

json 里还有 `median_ttft_ms` / `std_ttft_ms` / `mean_e2el_ms` 等字段，没有都铺到表里，需要时查 `04`。
另外每次运行还跑过一次热身 bench（`random_input_len`=1024、seed 999，`03_bench_params.tsv` 里 `备注` 标了「热身轮」），
它不是 15 种形状之一，下面不列；原始 json 在 `/tmp/mc2_probe/grid/<运行名>/warmup_c*.json`。

这份数据里没有逐请求记录（这批 bench 用的是 `vllm bench serve` 默认的 `--save-detailed=False`），
也没有 TPOT / ITL（`random_output_len`=1，vllm bench 只报 TTFT 与 E2EL）。

870 次 bench 全部 `completed` = `num_prompts`、`failed` = 0，所以表里的 `完成/失败` 列恒为 N/0，
保留它是为了和原始 json 对得上。

只想看结论（slot 相对 off 快还是慢、在哪些形状上、为什么）的，看 `/tmp/mc2_probe/SLOT_VS_OFF_总结.md`；
本文件只摆数据，不做判断。
