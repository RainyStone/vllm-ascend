4. 瓶颈定位：MooneP 内核的时长 85~99% 是『等对端』，不是传输

按单次时长 2ms 为界把每次调用分成「快速体」（纯计算/传输）与「等待尾」（跨 rank 汇合等待）：

moonep_dispatch_kernel12.31%9us99%17207.1ms9us
moonep_combine_kernel10.514%197us86%13786.6ms123us
结论：三件套合计 38.8s（4 rank），其中≈34.8s（90%）是等对端——折合每 rank 约 8.7s，占 41s 窗口的 21%。纯传输极快（dispatch 快速体均值仅 9μs/次）。等待的来源是各 rank 抵达集合点的时刻差：各 rank 的 attention/前序计算完成时间不同步，planning 的跨卡栅栏先到者空转。这正是与 off『等热点 rank』同源的现象，只是 slot 把它从 40ms 级长尾压到了 7~21ms 级、且发生在设备内核内（有机会用重叠藏掉）。
