统计口径（怎么读下面的表）
  • 轮次：同一个形状在同一个服务进程上重复跑的第几遍。每轮换一批 prompt（seed = 形状的 seed 序号 × 1000 + 轮次），换 seed 是为了避免上一轮的 prompt 被 prefix caching 命中而把 TTFT 压低。
  • 轮次 1 当热身剔掉：它是服务刚拉起后的第一遍，历史上偏慢；结论只看轮次 2、3。
  • 四个变化量，算式一律 (新 − 参照) / 参照 × 100%：(slot − off)/off = 本轮主结论（slot 相对 off）；(slot − slot0)/slot0 = real-T 归因（同轮同环境、与旧 slot 等价的回退腿）；(off 本轮 − off 旧)/off 旧 = 环境漂移（旧值取 H16 报告）；(slot 本轮 − slot 旧)/slot 旧 = 优化总效果（含环境漂移）。
  • 符号：TTFT / duration 这一类越小越好 → 负号 = 更快 = 好（绿）、正号 = 更慢 = 差（红）；吞吐这一类越大越好 → 正号 = 更快 = 好（绿）；数值两侧同向比较（对吞吐来说负号 = 吞吐掉 = 红）。
  • 变化逐轮各给一个（轮次 1 的值只是留档、不上色，不参与结论），另外每个变化量给一个「中位」列——先把两边各自取轮次 2、3 中位，再算变化。两种模式没有绝对好坏时（completed / failed / max_concurrent_requests）不上色。
  • 模态不稳：若同一模式保留的两轮之间相差超过 15%，该形状的表下会给出备注。
  • 这批 bench random_output_len=1，量与 E2EL 只差一个输出 token；报告只列 TTFT 家族与吞吐，E2EL 家族在原始 json 里仍有。也没有逐请求记录（bench 用默认 --save-detailed=False）。
