3. 机制：同一种等待，三种形态

MoonEP slot 与 off 的跨 rank 通信开销本质都是等待最慢的参与者，差异在于等待的决定因素与发生位置：

场景等待发生位置等待由什么决定量级（每 rank）结果
A · off（8k/8k）HCCL 集合通信（AI_CPU 内核）峰均比——热点 rank 的计算进度（s=2.48 时热点 rank 承担 62% 载荷）7.5s/窗口最贵
A · slot（8k/8k）MooneP planning/dispatch/combine 栅栏各 rank 到达栅栏的时刻差；8k 步同构，仅剩调度抖动5.2s/窗口低于 off → slot 获益
B · slot（16k 整步）同上同构长步，等待为低方差常数（每步 0ms，标准差 0）1.4s/窗口获益最大（−12.9%）
C · slot（16k 切分）同上步成本交替（chunk1/chunk2 的 attention 1:2~4）+ rank 间队列相位差；等待高方差（每步 424ms，标准差 265，极差 0~882）3.1s/窗口超过收益上限 → 受损

图 3 即机制的直接观测：整步场景每步等待收敛于近似常数（同构步、四 rank 同步推进的特征）；切分场景等待在 0~882ms 间波动（步成本交替与相位错位的特征）。planning 内核自身计算量在切分窗口内合计仅 23ms，等待占 99.9% 以上。

4. 优化方向（按三场景证据汇总）

#方向证据预期作用
1planning 栅栏等待与计算重叠（after_planning_hook 挂点已具备）三场景的通信开销 91~100% 为等待；B 每步 0ms、C 每步 424ms 均可实现重叠同时改善 B 与 C；C 的退化主体（planning 等待增量 +5.3s/轮）可大部分消除
2同 prompt 跨 chunk 复用 planSIM_ROUTE 下两 chunk 路由分布恒等、plan 输出一致消除一半 planning 栅栏汇合次数（C 场景等待事件 603→约 300）
3调度器 chunk 相位对齐C 场景等待方差 0~882ms vs B 的常数——方差为相位错位的直接签名将 C 的等待恢复至 B 的低方差常数水平
4降低 rank 间到达抖动（host 发射密度、内核数）A 场景 slot Free 45%；launch 次数较 off 多 68%压缩所有场景的常数等待部分
