0. 方法：这个「预测」是怎么来的

预测输入第 i 层 attention 之前的残差流（= 第 i−1 层的输出，hidden_states + residual）
预测方式把它送进 第 i 层自己的 post_attention_layernorm + gate，取 top-k(=8) ⇒ 得到「预测的专家计数直方图」
为什么可行残差结构 ⇒ 同一层 attention 前后的 hidden 相近 ⇒ 路由分布相近（本页就在验证这一点）
预测 plan把预测的 routing 再喂给 规划内核 跑一遍 ⇒ 得到「预测 plan」，取其 experts_to_copy[rank]（本卡要镜像的冗余专家 + 槽位）
对照真值真实 routing（本层实际输入）⇒ 真 plan（本层真实执行的规划结果）
为什么会有人关心真 plan 要等本层 dispatch 才算出来，prefetch 只能排在它后面、卡在关键路径上； 若能在 attention 期间就预测出 plan，就能把 prefetch 挪到和 attention 并行，掩盖掉它的延迟

1. 逐 (层, 专家) 的路由计数：预测 vs 真实

图例 / 坐标轴分别代表什么

横轴该 (层, 专家) 的预测路由 token 数（log 刻度）
纵轴同一 (层, 专家) 的真实路由 token 数（log 刻度）
每个点一个 (层, 专家) 组合 —— 共 层数 × 128 个专家 个点
红色虚线 y=x完美预测：点落在这条线上 = 预测值恰好等于真实值
点的深浅重叠密度（α=0.06 的散点叠加，越深代表越多点重合在那里）

怎么读

越贴近红色虚线越准。高计数区（热门专家）必须几乎贴线；低计数区（稀疏专家）允许散布，因为 1~2 个 token 的差异在绝对量上无意义 —— 规划器均衡看的是负载，由热门专家主导。

本次实测看出什么

余弦相似度 0.9863，高计数区几乎零偏离；只有极稀疏专家在 1~3 计数处有散布。最热专家（argmax）一致率 0.918，top-5 专家集合重合率 0.936。

2. 逐步、逐卡的负载占比：预测 vs 真实

图例 / 坐标轴分别代表什么

横轴某一步中该卡处理的真实行数占该步总行数的百分比 [%]
纵轴同一步、同一卡的预测占比 [%]
每个点一个 (步, 卡) 组合 —— 一步 = 48 个 MoE 层聚合（单层样本太小、噪声大，故按步聚合）
四个颜色rank 0（蓝）/ rank 1（橙）/ rank 2（绿）/ rank 3（红），即四张卡
黑色虚线 y=x完美预测
浅蓝带 ±10%相对误差 ±10% 的容差带；点落在带内 ⇒ 预测误差小于 10%
灰色点线 25%四卡完全均衡时的理论占比（1/4）

怎么读

点应沿 y=x 分布。注意这张图里的点并不都落在 25% 上 —— 它们横向铺开的宽度，就是真实存在的负载不均衡；纵轴同样铺开，说明预测把这种不均衡也复现出来了。

本次实测看出什么

点紧贴 y=x ✓；真实各卡占比在 20–26% 之间漂移（理想 25%），预测把「哪张卡偏忙」也跟住了 ✓。

5. 预测 plan vs 真实 plan：冗余专家选取命中率

图例 / 坐标轴分别代表什么

纵轴命中率（与真实 plan 逐层逐卡对比的相符比例）
第 1 根 exact逐槽完全相同：槽位与专家都对上（最严格口径）
第 2 根 expert set只看镜像专家集合是否相同，忽略落在哪个槽位
第 3 根 slot 0只看最重要的槽位 slot 0 放的是不是同一个专家
第 4 根 baseline对照组：不做任何预测，直接沿用「上一步的真实 plan」

怎么读

前三根越高越好；第四根是必须打败的基线 —— 如果预测还比不过「照抄上一步」，方案就没有价值。

本次实测看出什么

exact 0.805、专家集合 0.807、slot0 0.826，均高于基线 0.693 ⇒ 提前预测确实带来了额外信息 ✓（领先约 11 个百分点）。

术语表

行 / row一个 (token, 专家) 条目；MoE 计算量 ∝ 行数
冗余专家 / 镜像plan 把某个远端热门专家的行留在本地计算（预取它的权重到本地槽位），用来均衡各卡负载
槽位 / slot本卡存放被镜像专家权重的缓冲区；experts_to_copy[rank] 给出每个槽放哪个专家，−1 = 空槽
plan规划内核每层产出的调度方案：每行的目的地 dst、每卡要镜像的专家 experts_to_copy 等
prefill / decode处理 prompt 的阶段 / 逐 token 生成的阶段；两者负载量级相差约 100×
