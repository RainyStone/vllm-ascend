统计口径（怎么读下面的表）
  • 轮次：同一个形状在同一个服务进程上重复跑的第几遍。每轮换一批 prompt（seed = 形状的 seed 序号 × 1000 + 轮次），换 seed 是为了避免上一轮的 prompt 被 prefix caching 命中而把 TTFT 压低。
  • 轮次 1 当热身剔掉：它是服务刚拉起后的第一遍，历史上偏慢；结论只看轮次 2、3。
  • 变化：逐轮各给一个（轮次 1 的值只是留档，不参与结论），另外给一个「轮次 2、3 中位」的变化——先把两边各自取轮次 2、3 的中位，再算 (slot − off) / off。
  • 绿色/红色：按「变小更好」还是「变大更好」判 slot 相对 off 的方向；两种模式没有绝对好坏时（completed / failed / max_concurrent_requests）不上色。
  • 模态不稳：若同一模式保留的两轮之间相差超过 15%，该格下面的备注会写出来，并额外给出「两边都取低」与「两边都取高」两个口径的变化，用来判断符号稳不稳。
  • 这批 bench random_output_len=1，量与 E2EL 只差一个输出 token；报告只列 TTFT 家族与吞吐，E2EL 家族在原始 json 里仍有。也没有逐请求记录（bench 用默认 --save-detailed=False）。
