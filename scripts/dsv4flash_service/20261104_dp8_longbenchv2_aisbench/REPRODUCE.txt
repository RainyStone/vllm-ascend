复现一轮全新完整实验
以下步骤用于将来明确安排的新执行，本次提交检查没有运行服务或压测。
1. 按EXPERIMENT.md核对模型、数据集、原仓SDK和8卡资源，检查两份服务sh与两份aisbench配置。
2. 数据未准备时，先运行audit_lengths.py和prepare_dataset.py，生成data/selection_manifest.json
   与data/longbenchv2_full_le128k.json；已有数据应先核对哈希，不覆盖历史结果。
3. 在本目录创建独立执行目录和CURRENT_EXECUTION.json，例如：

python - <<'PY'
import json, shutil
from datetime import datetime
from pathlib import Path
from zoneinfo import ZoneInfo
root = Path.cwd()
stamp = datetime.now(ZoneInfo("Asia/Shanghai")).strftime("%Y%m%d_%H%M%S")
session = root / "data/executions" / ("run_" + stamp + "_manual")
session.mkdir(parents=True, exist_ok=False)
shutil.copy2(root / "data/selection_manifest.json", session / "selection_manifest.json")
(root / "CURRENT_EXECUTION.json").write_text(
    json.dumps({"session": str(session), "status": "prepared"}, indent=2))
print(session)
PY

4. 用上一步打印的绝对目录作为参数运行：
   python -u run_full_matrix.py <新执行目录>
   控制器依次执行off→Slot、Slot→off，独立起服，每台3轮，并在结束后自动校验、汇总与释放资源。
5. 查看matrix_status.py、执行目录remaining_state.json及RESULT.md。
   RESULT.md和rounds.csv取每台服务第2、3轮均值，同模式两台服务再等权平均。
   postprocess_when_complete.py用于本次历史修复版对照汇总，不是必需的通用执行入口。

补充验证
- diagnostics/包含独立的负载和固定请求诊断，不将诊断时间混入正式性能。
- precision_fix/weighted_combine_v1/tests/为唯一的算子测试代码，
  host124/tests/中的启动脚本已指向共享原仓SDK。
- 所有同模式、跨模式首token比较只描述1-token文本一致性，不等价于LongBench任务准确率。
- 老基线results.json的duration_seconds字段历史上误存毫秒；新版汇总脚本已换算为秒。
  TTFT与输入吞吐字段不受此历史标签错误影响。
